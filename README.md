# AutoGO

Площадка объявлений о продаже авто, дополненная личным гаражом владельца:
трекером заправок/зарядок, журналом ТО, форумом, технической документацией
и ИИ-помощником поиска по автомобильным форумам.

## Стек

- **Backend:** Node.js + Express
- **БД:** встроенный в Node модуль `node:sqlite` (файл `data/autogo.db`) — без установки отдельной СУБД
- **Auth:** email+пароль, JWT в httpOnly-cookie, пароли хешируются bcrypt
- **Frontend:** тот же статический HTML/CSS/JS, что был в исходном репозитории (Bootstrap 5), плюс несколько новых страниц для новых разделов. Без сборки — отдаётся сервером как есть.

## Быстрый запуск

```powershell
npm install
copy .env.example .env
npm start
```

Откройте `http://localhost:3000`. По умолчанию сервер слушает порт из `.env` (`PORT`, по умолчанию 3000).

При первом запуске БД создаётся автоматически и заполняется демо-данными:
категориями форума и несколькими документами техдокументации, плюс два демо-аккаунта:

| Email | Пароль | Роль |
|---|---|---|
| `user@autogo.local` | `user12345` | обычный пользователь |
| `admin@autogo.local` | `admin123` | администратор (модерация форума, добавление техдокументации) |

Можно также зарегистрировать новый аккаунт через кнопку «Регистрация».

## Что реализовано (по пунктам ТЗ)

1. **Трекер заправок/зарядок** — раздел «Гараж» → вкладка «Заправки/зарядки» у каждого автомобиля.
   Добавление записей (заправка топливом или зарядка для EV), история, автоматический расчёт
   статистики: суммарные затраты, суммарный объём, средний расход на 100 км, стоимость за км.
   API: `server/routes/garage.js` (`/api/garage/:carId/fuel-logs*`, `/fuel-stats`).

2. **ТО (техобслуживание)** — вкладка «ТО» у автомобиля: журнал работ (что сделано, дата, пробег,
   стоимость), с указанием, когда нужно следующее ТО (по пробегу и/или по дате). Система
   автоматически подсвечивает просроченные напоминания.
   API: `/api/garage/:carId/maintenance*`, `/maintenance-reminders`.

3. **Форум** — разделы, темы, сообщения, ответы. Базовая модерация: автор или администратор может
   удалить своё/любое сообщение, администратор может закрыть тему для ответов или удалить её целиком.
   Страницы: `forum.html`, `topic.html`. API: `server/routes/forum.js`.

4. **ИИ-агент поиска по форумам** — страница «Помощник» (`agent.html`). Принимает запрос
   (+ марку/модель), подбирает релевантную информацию. Реализация и её мотивация подробно описаны
   в `server/services/forumSearch.js`: прямой скрейпинг поисковиков (DuckDuckGo/Bing) на практике
   упирается в их анти-бот защиту (капча), которую обходить нельзя и не нужно — поэтому агент
   использует локальную базу знаний по типовым автомобильным темам с подбором релевантности по
   ключевым словам, плюс список реальных автофорумов для дальнейшего ручного поиска. Если прописать
   в `.env` переменные `SEARCH_API_URL`/`SEARCH_API_KEY` (любой JSON-совместимый поисковый API —
   Bing Web Search, SerpAPI и т.п.), агент будет использовать уже живые внешние результаты. Все
   сетевые вызовы обёрнуты в таймаут и try/catch — сбой внешнего источника не ломает ответ.

5. **Техническая документация** — раздел `docs.html`: регламенты ТО, мануалы, схемы, с фильтрами
   по марке/модели/категории и полнотекстовым поиском. Администратор может добавлять новые документы
   через API (`POST /api/docs`).

6. **Инфо об авто** — карточки автомобилей в «Гараже»: марка, модель, год, пробег, VIN, госномер,
   тип топлива, объём двигателя, привязаны к владельцу (`user_id`).

## Структура проекта

```
server/
  index.js            — точка входа Express
  db.js               — схема SQLite и сидирование демо-данных
  middleware/auth.js  — JWT-аутентификация
  routes/             — auth, garage (авто+заправки+ТО), forum, docs, agent, health
  services/forumSearch.js — логика ИИ-агента поиска
*.html, *.js, style.css  — фронтенд (как в исходном репозитории + новые страницы)
nav.js                — общее подменю разделов и авторизация на всех страницах
tests/                — автоматические тесты (node:test)
scripts/healthcheck.js — ручная проверка запущенного сервера
team-instructions/    — инструкции для участников команды по коммитам от своего имени
```

## Проверка работоспособности

Автотесты (поднимают сервер на отдельной временной БД):

```powershell
npm test
```

Healthcheck запущенного сервера (сервер должен быть уже запущен, `npm start` в другом окне):

```powershell
npm run healthcheck
```

Обе проверки на момент написания README проходят полностью.

## Известные ограничения (честно, по изначальному демо-макету)

Исходный репозиторий был статическим макетом: часть кнопок в каталоге объявлений и админке были
подключены к `alert()`-заглушкам (оплата премиума, проверка VIN через внешний сервис, сообщение
продавцу, жалобы, редактирование справочников в админке). Эти части не входили в 6 пунктов
технического задания и остались демонстрационными — трогать их означало бы отдельный большой кусок
работы (платежи, модерация объявлений, реальные продавцы), не относящийся к запрошенным функциям.
Все 6 запрошенных функций (трекер, ТО, форум, ИИ-агент, документация, карточки авто) работают
по-настоящему, end-to-end, с реальной БД.

## Переменные окружения

См. `.env.example`. Обязательные: `PORT`, `JWT_SECRET` (смените на случайную строку перед
реальным использованием). `SEARCH_API_URL`/`SEARCH_API_KEY` — опционально, для подключения
настоящего поискового API к ИИ-агенту.
