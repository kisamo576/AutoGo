# AutoGO

Площадка объявлений о продаже авто с личным гаражом владельца: трекером
заправок/зарядок, журналом ТО, форумом, технической документацией и
помощником поиска по автомобильным форумам.

## Стек

- **Backend:** Node.js + Express
- **БД:** встроенный в Node модуль `node:sqlite` (файл `data/autogo.db`) — без установки отдельной СУБД
- **Auth:** email и пароль, JWT в httpOnly-cookie, пароли хешируются bcrypt
- **Frontend:** тот же статический HTML/CSS/JS, что был в исходном репозитории (Bootstrap 5), плюс несколько новых страниц для новых разделов. Без сборки — отдаётся сервером как есть.
- **Дизайн:** единая система токенов в `style.css` (цвет, типографика на Sora/Inter, радиусы, тени), общие состояния hover/active/disabled/focus, один визуальный язык на всех страницах.

## Быстрый запуск

```powershell
npm install
copy .env.example .env
npm start
```

Откройте `http://localhost:3000`. Сервер слушает порт из `.env` (`PORT`, по умолчанию 3000).

При первом запуске БД создаётся автоматически и заполняется демо-данными:
категориями форума и несколькими документами техдокументации, плюс два демо-аккаунта:

| Email | Пароль | Роль |
|---|---|---|
| `user@autogo.local` | `user12345` | обычный пользователь |
| `admin@autogo.local` | `admin123` | администратор (модерация форума, добавление техдокументации) |

Можно также зарегистрировать новый аккаунт через кнопку «Регистрация».

## Функции

1. **Трекер заправок/зарядок** — вкладка «Заправки/зарядки» у каждого автомобиля в «Гараже».
   Добавление записей (заправка топливом или зарядка для EV), история, автоматический расчёт
   статистики: суммарные затраты, суммарный объём, средний расход на 100 км, стоимость за км.
   API: `server/routes/garage.js` (`/api/garage/:carId/fuel-logs*`, `/fuel-stats`).

2. **ТО (техобслуживание)** — вкладка «ТО» у автомобиля: журнал работ (что сделано, дата, пробег,
   стоимость) с указанием, когда нужно следующее ТО (по пробегу и/или по дате). Просроченные
   напоминания подсвечиваются отдельно.
   API: `/api/garage/:carId/maintenance*`, `/maintenance-reminders`.

   Там же — вкладка «Запчасти» (журнал замен: деталь, дата, пробег, стоимость) и вкладка
   «Проверки» (техосмотр, страховка и другие проверки с датой окончания действия и
   напоминанием, когда срок подходит или уже истёк).
   API: `/api/garage/:carId/parts*`, `/api/garage/:carId/inspections*`, `/inspection-reminders`.

3. **Форум** — разделы, темы, сообщения, ответы. Базовая модерация: автор или администратор может
   удалить своё/любое сообщение, администратор может закрыть тему для ответов или удалить её целиком.
   Страницы: `forum.html`, `topic.html`. API: `server/routes/forum.js`.

4. **Помощник поиска по форумам** — страница `agent.html`. Принимает запрос (+ марку/модель) и
   подбирает релевантную информацию. Поисковые системы блокируют автоматические запросы капчей,
   поэтому вместо скрейпинга используется локальная база знаний по типовым автомобильным темам
   с подбором релевантности по ключевым словам, плюс список реальных автофорумов для дальнейшего
   ручного поиска. Если указать в `.env` переменные `SEARCH_API_URL`/`SEARCH_API_KEY` (любой
   JSON-совместимый поисковый API — Bing Web Search, SerpAPI и т.п.), помощник будет использовать
   живые внешние результаты. Логика — в `server/services/forumSearch.js`.

5. **Техническая документация** — раздел `docs.html`: регламенты ТО, мануалы, схемы с фильтрами
   по марке/модели/категории и полнотекстовым поиском. Администратор может добавлять новые документы
   через API (`POST /api/docs`).

6. **Карточки автомобилей** — марка, модель, год, пробег, VIN, госномер, тип топлива, объём
   двигателя; каждая машина привязана к владельцу (`user_id`).

Каталог объявлений (`cars.js`) содержит 130 моделей по 10 маркам без дублей. У моделей без
собственного фото в `images/` автоматически подставляется единый плейсхолдер вместо битой
картинки или внешнего сервиса.

## Структура проекта

```
server/
  index.js                — точка входа Express
  db.js                   — схема SQLite и сидирование демо-данных
  middleware/auth.js      — JWT-аутентификация
  routes/                 — auth, garage (авто+заправки+ТО), forum, docs, agent, health
  services/forumSearch.js — логика помощника поиска
*.html, *.js, style.css   — фронтенд (как в исходном репозитории + новые страницы)
nav.js                    — общее подменю разделов и авторизация на всех страницах
tests/                    — автоматические тесты (node:test)
scripts/healthcheck.js    — ручная проверка запущенного сервера
team-instructions/        — инструкции для участников команды по коммитам от своего имени
```

## Проверка работоспособности

Автотесты (поднимают сервер на отдельной временной БД):

```powershell
npm test
```

Healthcheck запущенного сервера (сервер должен быть уже запущен, `npm start` в другом окне):

```powershell
npm run healthcheck
```

## Известные ограничения

Исходный репозиторий был статическим макетом: часть кнопок в каталоге объявлений и админке
подключены к `alert()`-заглушкам (оплата премиума, проверка VIN, сообщение продавцу, жалобы,
редактирование справочников в админке). Эти части не входят в 6 реализованных функций и остаются
демонстрационными — это отдельная работа (платежи, модерация объявлений, реальные продавцы), не
относящаяся к трекеру, ТО, форуму, помощнику поиска, документации и карточкам авто. Все 6 функций
работают по-настоящему, end-to-end, с реальной БД.

## Переменные окружения

См. `.env.example`. Обязательные: `PORT`, `JWT_SECRET` (смените на случайную строку перед
реальным использованием). `SEARCH_API_URL`/`SEARCH_API_KEY` — опционально, для подключения
настоящего поискового API к помощнику.
